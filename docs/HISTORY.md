## 2. 要望と決定の経緯（時系列）

1. **きっかけ**：定期テストの問題用紙（Word）を毎回、解答番号・体裁を手で直すのが面倒でミスの元。アプリ化したい。
   マークシート式（自作の採点アプリで採点）、選択肢はカタカナ（ア〜）、記述は原則なしだが機能は欲しい。
   → 空欄番号・記号・正答を自動化。入力データ（JSON）を唯一の正にし、出力は毎回計算（`compile`）。
2. **開発の方針（ユーザーの恒常的な好み）**：担当が替わっても保守できる持続可能性／バックアップ機能／シンプルで使いやすいUI。
   → 単一HTML・外部ライブラリなし・先頭に引き継ぎコメント・「使い方・引き継ぎ」ボタン・バックアップJSON・履歴・複製。
3. **問題の種類**：語群選択（空欄補充。サンプルの元形式）／選択問題／正誤／記述。語群は「正解＋ダミー」から自動生成。
   空欄記法 `{{語句}}`、同じ空欄の再登場は `{{@語句}}`（元の問題用紙に「（２）」が文中に複数回出るため）。
4. **出力**：画面プレビュー、印刷/PDF、Word（.docx。自前のZIP/XML生成。外部ライブラリなし）、正答一覧、正答CSV。
5. **ルビ**：`[漢字|かんじ]` 記法。表示ON/OFFで同じデータからルビ付き版・なし版。
6. **教科書体**：フォント選択に「UD デジタル 教科書体 NP-R」「HG教科書体」を追加。
7. **自動ルビ（A＋B併用）**：外国籍の生徒が多く、基本的に**全漢字にルビを振る**運用。
   - A: kuromoji.js＋mecab-ipadic を `ruby-engine.js` に埋め込み（通信なしで動く偽XHRで辞書を供給）。
   - B: 読みの登録辞書（`store.userDict`）。優先順位は **手書き > 登録辞書 > 標準辞書(BUILTIN_DICT) > 自動**。
   - 辞書エンジンは遅延読み込み。無くても他機能は動く（登録辞書の最長一致のみで動作）。
   - 「ルビの確認・辞書」ダイアログで、出てきた漢字語と読みを一覧・修正・登録。辞書はバックアップに含む。
   - 入力データは書き換えない（表示時に付与）。
8. **ファイル名の文字化け**（ユーザー報告）→ 配布ファイル名を半角英数に変更（`TestMaker.html` 等）。
9. **改ページ**：「問題の切れ目で改ページして体裁が悪い」→ 語群を本文と同ページに強制する指定が強すぎて大きな空白が出ていた。
   `keepBank`（本文の最後の数行と語群を同ページに）と `pageMode`（詰める／大問ごとに改ページ）の設定にして緩和。
10. **白黒印刷**（ユーザー指定）：グレー表現不可 → 灰色塗りを全廃し白地＋太枠線に。大問番号は黒地白抜きのまま。
11. **教科書体でWord出力すると体裁がずれる**（ユーザー報告）：原因は行間を「自動(倍率)」にしていたことと推定
    → 行間を「最低値(atLeast)」の固定寄りに。教科書体の太字は NP-B ファミリを直接指定。
12. **PDFの左上に日時が出る**（ユーザー報告）：Chrome既定のヘッダ。`@page{margin:0}` ＋ thead/tfoot の余白で回避。
    副作用：印刷/PDFではページ番号が出ない（Wordは出る）。ページ下の文言は `position:fixed` で各ページ下に出す。
13. **採点アプリとの統合**：ユーザーは採点アプリを Claude Code で完成済み。統合の方向。
    → まず「連携」（採点用JSONを渡す）、画面統合は 1〜2学期運用後に判断、という段階案。`採点用JSON` ボタンを実装。
    成績（個人情報）は問題データ・バックアップと分離する方針。

## 3. 実装済み機能の一覧

- エディタ：基本設定、大問カード（並べ替え・複製・削除・折りたたみ）、種類別フォーム、警告一覧
- 語群：自動シャッフル（語句ハッシュで固定。語を足しても他の並びが動かない）／出現順／手動
- 自動採番：空欄・設問の通し番号、記述は「記1…」、記号セット（ア / ①… / A…）、最大選択肢数の警告
- 出力：HTML印刷・Word(.docx、ルビはWordのルビ機能)・正答一覧・正答CSV・採点用JSON（schema 1）
- 保存：localStorage（キー `testmaker:v1`）、履歴10分ごと40件、バックアップJSON（テスト＋ルビ辞書）、
  読み込みは「新しいテストとして追加」（既存を上書きしない）、辞書は不足分だけ追加
- 複製（学期ごとの再利用）、新規作成時は設定を引き継ぎ

## 4. 未確認・未解決（Claude Codeで最初に潰したい）

1. **実機のWordでの見た目**：LibreOffice でのみ確認。教科書体は開発環境に無く、実機未確認。
   → 実機で崩れる箇所があればユーザーが報告する。行間・語群の列・ルビ付き行の高さが怪しい。
2. **PDFの日時ヘッダが消えたか**：開発環境（ヘッドレス）では確認不可。実機のChrome/Edgeで要確認。
   消えない場合は印刷ダイアログで「ヘッダーとフッター」を外す運用。
3. **自動ルビの読みの精度**：IPAdicは古く誤読がある（例：語→かたり、令和）。標準辞書 `BUILTIN_DICT` に令・語のみ補正。
   「進数」「語群」など技術・学校用語を実運用で登録していく必要がある。
4. **印刷でページ番号が出ない**（上記12の副作用）。必要なら別方式を検討。
5. **サンプルの正答は推定**：元の問題用紙に正答が無かったため文脈から推定。27〜30が全て「間違い」は要確認。
6. **採点アプリの仕様は未確認**：この開発側は採点アプリを見ていない。連携の設計は Claude Code が現状調査してから。
7. 大問番号の黒地白抜きが印刷機で見づらい場合は、枠線のみの形へ変更可能。

## 6. 環境メモ（再現・保守のため）

- npm レジストリはこの開発環境ではポリシーで拒否されたため、kuromoji は GitHub（takuyaa/kuromoji.js、commit 71ea847…）から取得。
  `tools/build-ruby-engine.js` の冒頭に再生成手順あり（`git clone` → `node build-ruby-engine.js <repo> ruby-engine.js`）。
- ライセンス：kuromoji.js は Apache-2.0、辞書は mecab-ipadic-2.7.0-20070801（NAIST。著作権表示と免責の同梱が必須）。
  `ruby-engine.js` 冒頭に全文を入れてある。再配布時は丸ごと渡すこと。
- 動作確認は Playwright(Chromium)＋LibreOffice（docx→PDF）で実施。`window` のグローバル関数
  （`compile` `cur` `buildDocx` `buildKeyJSON` `renderPaperHTML` など）を `page.evaluate` で直接呼べる。
- 配布物の日本語ファイル名は文字化けしたため禁止（半角英数のみ）。
- 重い辞書は別ファイルに分離し遅延読み込み（HTML本体は約100KBを維持）。
